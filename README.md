# nginx-manager — простое управление сайтами на VPS

Интерактивный bash-скрипт для упрощённого создания, удаления, включения/выключения сайтов (виртуальных хостов) в nginx. Дополнительно позволяет устанавливать популярные веб-пакеты, управлять SSL-сертификатами через Certbot, контролировать порты через UFW и настраивать автоматические хуки для Certbot. Скрипт сам устанавливает себя в `/usr/local/bin/nginx-manager` при первом запуске.

---

## 🔥 Особенности

- ✅ Интерактивное меню с цветовым оформлением  
- ✅ Создание сайта за 30 секунд (статический или прокси)  
- ✅ **Показ всех сайтов** – видит конфиги даже без расширения `.conf`  
- ✅ Работа с **внешними сайтами** (созданными не скриптом) – с подтверждением перед удалением/переключением  
- ✅ Удаление пакетов (PHP, MySQL, PostgreSQL, SQLite3, Certbot) с отображением установленных версий  
- ✅ Установка пакетов с выбором или всех недостающих одной кнопкой  
- ✅ **Полноценное управление SSL-сертификатами**:  
  - получение сертификата для домена (с опцией добавить `www`)  
  - обновление всех сертификатов  
  - просмотр существующих сертификатов  
  - **интерактивный режим** `certbot --nginx` – выбор доменов из списка  
- ✅ **Управление портами (UFW)**:  
  - установка UFW  
  - открытие/закрытие портов (TCP/UDP)  
  - включение/выключение фаервола  
- ✅ Настройка **hooks для Certbot** – автоматическое открытие порта 80 перед запуском и закрытие после  
- ✅ **Информация о скрипте** – версия, путь, возможность удалить сам скрипт  
- ✅ Проверка синтаксиса nginx и автоматическая перезагрузка  
- ✅ Самоустановка в систему – доступен как `sudo nginx-manager`

## 📦 Установка за 1 минуту

Скопируйте скрипт на VPS и запустите:

```bash
curl -fsSL https://raw.githubusercontent.com/hargluk/nginx-manager/refs/heads/main/nginx-manager-installer.sh | sudo bash
```

Либо (если предпочитаете `wget`):

```bash
wget -O nginx-manager-installer.sh https://raw.githubusercontent.com/hargluk/nginx-manager/refs/heads/main/nginx-manager-installer.sh && chmod +x nginx-manager-installer.sh && sudo ./nginx-manager-installer.sh
```

При первом запуске скрипт предложит установить себя в `/usr/local/bin/nginx-manager`. Согласитесь — после этого управление сайтами будет доступно одной командой:

```bash
sudo nginx-manager
```

> Если вы откажетесь от установки, скрипт продолжит работу, но вы не сможете вызывать его из любого места.

## 📋 Меню

После запуска откроется главное меню:

```
======================================
      Управление сайтами nginx
======================================
1. Создать сайт
2. Список всех сайтов
3. Удалить сайт
4. Вкл/Выкл сайт
5. Перезагрузить nginx
6. Установить пакеты (PHP, MySQL, PostgreSQL, SQLite3, Certbot)
7. SSL сертификаты (Certbot)
8. Управление портами (UFW)
9. Настроить Certbot hooks (ufw: открыть/закрыть порт 80)
10. Информация о скрипте и удаление
0. Выход
======================================
```

### 1. Создать сайт

- Введите **короткое имя** (например, `mysite`) — оно будет использовано для папки и имени конфига.
- Введите **домен** (например, `example.com`) — он будет подставлен в `server_name`.
- Выберите **тип**:
  - **Статика** — обычный статический сайт (HTML/CSS/JS).
  - **Прокси** — перенаправление на локальный порт (например, для приложения на Node.js, порт 3000).
- При создании автоматически:
  - Создаётся папка `/var/www/<имя>`
  - Создаётся `index.html` (если пусто)
  - Генерируется конфиг nginx в `/etc/nginx/sites-available/<имя>.conf`
  - Создаётся симлинк в `sites-enabled`
  - Проверяется конфиг и перезагружается nginx

### 2. Список всех сайтов

Показывает **все** конфиги, найденные в `/etc/nginx/sites-available/` (независимо от наличия расширения `.conf`).  
Для каждого сайта выводится:
- Имя
- Домен (если удаётся извлечь из конфига)
- Метка: `[свой]` (создан скриптом) или `[внешний]` (создан вручную или другим инструментом)
- Статус: `включён` или `выключен` (проверяется наличие симлинка в `sites-enabled`)

### 3. Удалить сайт

Выводит список всех сайтов (своих и внешних).  
При выборе сайта:
- Если сайт **свой** — удаляется конфиг и симлинк (папка `/var/www/<имя>` удаляется по запросу).
- Если сайт **внешний** — скрипт предупреждает об этом и запрашивает подтверждение перед удалением.

### 4. Вкл/Выкл сайт

Переключает симлинк в `sites-enabled`.  
Для внешних сайтов также запрашивается подтверждение.

### 5. Перезагрузить nginx

Проверяет конфигурацию `nginx -t` и перезагружает сервис.

### 6. Установить пакеты

Отображает список пакетов (PHP, MySQL, PostgreSQL, SQLite3, Certbot) с их текущим статусом и версией (если установлены).  
Вы можете:
- Ввести номера пакетов через пробел (например, `1 3 5`) – для установки (если не установлены) или удаления (если уже установлены, спросит подтверждение).
- Нажать `9` – установить все недостающие пакеты.
- Нажать `0` – выйти.

После установки/удаления статусы обновляются автоматически.

### 7. SSL сертификаты (Certbot)

При входе в это подменю скрипт проверяет, установлен ли Certbot. Если нет – предлагает установить его прямо сейчас.  
Подменю содержит:

```
1. Получить сертификат для домена (с www)
2. Обновить все сертификаты
3. Показать существующие сертификаты
4. Запустить certbot --nginx (интерактивный режим)
0. Назад
```

- **Пункт 1** – запрашивает домен и спрашивает, нужно ли добавить поддомен `www`. После успешного получения сертификата перезагружает Nginx.
- **Пункт 2** – выполняет `certbot renew`.
- **Пункт 3** – показывает список действующих сертификатов.
- **Пункт 4** – запускает `certbot --nginx` в интерактивном режиме: вы можете выбрать домены из списка с помощью пробела и стрелок, а также добавить дополнительные.

### 8. Управление портами (UFW)

Позволяет управлять фаерволом UFW. Если UFW не установлен – предлагает установить.  
Доступные действия:

- Показать статус и правила
- Открыть порт (указывается номер и протокол tcp/udp)
- Закрыть порт (удалить правило)
- Включить UFW
- Выключить UFW
- Назад

При открытии порта 22 (SSH) автоматически добавляется правило, чтобы не потерять доступ.

### 9. Настроить Certbot hooks (ufw)

Создаёт или обновляет файл `/etc/letsencrypt/cli.ini`, добавляя:

```
pre-hook = ufw allow 80/tcp
post-hook = ufw delete allow 80/tcp
```

Это позволяет Certbot автоматически открывать порт 80 перед запуском (если используется режим standalone) и закрывать после.  
Перед настройкой проверяется установка UFW и открытость порта 22.

### 10. Информация о скрипте и удаление

Показывает:
- Название
- Версию (например, `5.3`)
- Путь к исполняемому файлу
- Автора

Предлагает удалить скрипт (с подтверждением). После удаления скрипт завершает работу.

## 📁 Структура, создаваемая скриптом

```
/var/www/
  └── <имя>/
      └── index.html

/etc/nginx/
  ├── sites-available/
  │   ├── <имя>.conf    (для сайтов, созданных скриптом)
  │   └── <имя>         (может быть без расширения, если конфиг внешний)
  ├── sites-enabled/
  │   └── <имя>.conf -> ../sites-available/<имя>.conf
  └── .my_sites            (файл со списком имён, созданных скриптом)
```

> Скрипт теперь корректно работает с конфигами как с расширением `.conf`, так и без него.

## 📝 Примеры конфигураций

### Статика

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;
    root /var/www/mysite;
    index index.html index.htm index.php;
    location / {
        try_files $uri $uri/ =404;
    }
}
```

### Прокси

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name api.example.com www.api.example.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 🔒 Безопасность

- Все операции требуют `sudo`.
- Скрипт не даёт удалить или переключить внешний сайт без дополнительного подтверждения.
- При удалении сайта папка `/var/www/<имя>` удаляется только после явного согласия.
- Скрипт не изменяет конфиги других веб-серверов.
- Включение UFW всегда открывает порт 22 (SSH) по умолчанию, чтобы избежать потери доступа.

## 🗑️ Удаление скрипта

Если вы больше не хотите использовать `nginx-manager`, выполните:

```bash
sudo rm /usr/local/bin/nginx-manager
```

Или выберите пункт меню **10** и подтвердите удаление.

Созданные сайты и конфиги останутся нетронутыми.
